# Update Skill — 展示模板

> 卡片输出规则：
> - JSON 必须单行，不含换行符
> - 有 `_suggestedCard` 时原样输出，禁止手工拼凑
> - 无卡片场景（追问、ambiguous 候选选择、错误说明）→ 纯自然语言

---

## 脚本自动生成的卡片

以下卡片均由脚本在 `_suggestedCard` 中自动生成，AI 只需**原样输出 `_suggestedCard` 字符串（块外零字符）**：

| 卡片 | 生成脚本 | 触发条件 |
|------|---------|---------|
| `visit-plan-result-card` | `plan-list`（多条结果）| 路径 A/B 候选计划查询返回多条 |
| `edit-visit-plan-card` | `plan-list`（1 条）/ `plan-card` | 路径 A 单条结果或用户选定计划后 |
| `confirm-edit-visit-plan-card` | `build-confirm-card` | 路径 B 所有槽位 batch-resolve ok 后 |
| `action_result` + `visit-plan-cancelled-card` | `direct-update` | 写操作成功/失败时自动构建 |

## [modifyFields 枚举值] — `build-confirm-card` 的 `--modify-fields` 参数取值

> **AI 需要此表**：调用 `build-confirm-card` 时，`--modify-fields` 参数按此表选取枚举值。

| 枚举值 | 含义 | 填入条件 |
|--------|------|---------|
| `visitType` | 拜访类型（本地/出差）| 用户改了 visitType |
| `travelApplyNo` | 差旅单号 | 用户改了差旅单号 |
| `visitPurposeLabel` | 拜访目的 | 用户改了拜访目的 |
| `planVisitTime` | 计划拜访时间 | 用户改了拜访时间 |
| `planVisitAddress` | 计划拜访地址 | 用户改了拜访地址 |
| `visitObjectType` | 拜访对象类型 | 用户改类型为 `ad_customer`/`agent`/`provider` 时填入；**改为 `store` 时不填** |
| `customerType` | 新客/老客 | 用户改了新客老客，且当前类型为 `ad_customer` 或 `store` |
| `businessLicense` | 营业执照信息 | 当前类型为 `ad_customer`/`agent`/`provider` 且用户改了客户名 |
| `store` | 门店信息 | 用户改类型为 `store` 或当前为 `store` 且改了门店信息；**填 `store` 时不要同时填 `visitObjectType`** |
| `accompanyUserName` | 陪访人列表 | 用户改了陪访人 |

**`visitObjectType` 与 `store` 互斥规则**：
- 用户说"改为门店"/"改为锅圈食汇"等 → 只填 `store`，**禁止填 `visitObjectType`**
- 用户说"改为广告客户"/"改为代理商"/"改为团购服务商"等 → 填 `visitObjectType` + `businessLicense`
- **禁止同时填 `visitObjectType` 和 `store`**

> `modifyFields` 可同时包含多个枚举值，如 `"modifyFields":["planVisitAddress","visitPurposeLabel"]`

## [ambiguous 候选] — pending_ambiguous_slot 非空时纯自然语言输出

**禁止输出任何卡片协议块**。一次只展示一个槽位的候选，禁止同时选客户+地址。用户回序号后，batch-resolve 的 `raw` 必须是对应候选完整名称（或 poiId），禁止传 `"1"`。

> 术语屏蔽、处理过程屏蔽、槽位确认记录屏蔽统一由 SKILL.md「🔴 内部术语强制扫描」红线约束，本节不再重复。

### 输出格式模板（强制，违反即整条重写）

**整条回复 = 首行提示语 + 候选列表 + 末尾提示语，三部分按下方模板照填，禁止增减任何字符。**

> **🔴 首字符硬校验（违反即整条作废重写）**：
> - 模板 A/B/C 首字符必须是 `找`（`找到多个匹配的...`）
> - 模板 D 首字符必须是 `请`（`请问该客户是新客还是老客？`）
> - **若回复首字符不是 `找` 或 `请`** → 说明首行前加了"pendingAmbiguousSlot 为...""visit_object_info 有...""根据 skill 指令..."等内部话术 → 整条作废，从模板首行重新输出
> - **禁止任何前言/开场白/状态描述**：`pendingAmbiguousSlot 为 visit_object_info（门店），需要先展示门店候选列表。` / `visit_object_info 有多个候选，需要先解决。` / `根据 skill 指令展示候选：` / `现在处理这个槽位。` 等全部禁止，直接从模板首行开头

#### 模板 A — 客户候选（visit_object_info，类型为 ad_customer/agent/provider）

> ⛔ **整条回复第一个字必须是「找」**，前面不能有任何字符（包括空格、换行、说明文字）。
> **若第一字不是「找」** → 说明首行前混入了 `pendingAmbiguousSlot 为 xxx` 等内部话术 → **删掉前面所有内容，从「找到多个匹配的客户」重新开始写**。

首行固定：`找到多个匹配的客户，请选择：`
候选每行格式：`{序号}. {corporationName}（{regCity}）`，**每项必须独占一行**，带序号 `1.` `2.` ...
- `regCity` 仅在有值时显示，无值时只输出 `{序号}. {corporationName}`，括号省略
末行固定（单独一行）：`请回复序号，或输入更精确的名称重新搜索`

> **🔴 每项必须独占一行，禁止合并到一行**。候选项之间用换行符 `\n` 分隔，不是空格。输出前检查：每个候选必须以 `序号.` 开头单独成行。

示例：
```
找到多个匹配的客户，请选择：
1. 湖北三丰智能装备有限公司
2. 湖北长旭智能装备有限公司
3. 湖北鑫瑞隆智能装备有限公司（湖北省-武汉市）
4. 湖北天栋智能设备有限公司
5. 湖南积木智能装备有限公司（湖南省-长沙市）

请回复序号，或输入更精确的名称重新搜索
```

> 🔴 末行「请回复序号，或输入更精确的名称重新搜索」前必须有一个空行，单独成段，禁止紧跟候选列表末尾。

**❌ 错误示例**（首行前加了内部话术，整条作废）：
```
pendingAmbiguousSlot 为 visit_object_info（客户），需要先展示客户候选列表。
找到多个匹配的客户，请选择：
1. 湖北三丰智能装备有限公司
...
```
或
```
visit_object_info 有多个候选，需要先解决。按规则只展示 pendingAmbiguousSlot 的候选。
找到多个匹配的客户，请选择：
...
```

**✅ 正确示例**（整条回复只有首行+候选列表+空行+末行，无其他字符）：

### 格式红线

- **整条回复只能是上述四个模板之一**，禁止首行自拟、禁止末行自拟、禁止候选行加任何额外字符
- **禁止输出思考过程**：首行前不得有"我找到了""现在需要""有两个字段""根据"等任何说明文字，直接以模板首行开头
- **禁止候选行带类型标签**（如"广告客户"/"代理商"/"团购服务商"等）
- **候选 100% 来自 `candidatesJson`**，禁止凭记忆编造。若 `candidatesJson` 为空，追问用户「请提供更精确的名称」

### 用户回选后的 raw 映射

| 候选类型 | 用户选择后 `raw` 取值 |
|---------|----------------------|
| 客户（ad_customer/agent/provider） | 取选中候选项的 `corporationName` 字段值 |
| 地址（plan_visit_address） | 取选中候选项的 `poiName` 字段值 |
| 门店（store） | 取选中候选项的 `poiId` 字段值（数字 ID，不是名称） |
| customer_type | 取选中候选项的枚举值（`新客`/`老客`） |

> **禁止把序号 `"1"` 当 `raw` 提交**；**禁止把 `"北京市"` 等部分字段当 `raw` 提交**。
